# :car:ui

二开自研车机 UI（Jetpack Compose）。产品名 **DBPlay**。

> 视觉规范的唯一依据是仓库根目录的 **`DBPlay-UI-DESIGN.md`**。
> 本文只讲"代码在哪、为什么这么组织"，不讲具体色值和间距。

## 依赖方向（硬性约束）

```
:car:ui  →  :car:api   （仅此一个项目依赖）
```

`build.gradle.kts` 里只声明了 `api(project(":car:api"))`。
只要这一行不变，UI 就**不可能**碰到 CarPlay 协议核心——
不依赖 `:shared`、`:common`、`:car:core-bridge`、任何 `:car:platform-*`。

## 设计要点

### 1. Design System 是唯一取值来源

界面代码里**不允许**出现 `Color(0xFF...)`、裸 `16.dp`、字面量字号。
全部通过 `CarTheme.colors` / `CarTheme.type` / `CarTheme.dimens` / `CarTheme.shapes`。
这样"整体调 UI"只需改 `theme/` 下的几个文件。

自查（在仓库根目录执行，命中即违规）：

```bash
grep -rn "Color(0x" car/ui/src/main/java | grep -v "/theme/"
grep -rn "[0-9]\+\.dp" car/ui/src/main/java | grep -v "/theme/" | grep -v "0\.dp"
```

### 2. 分辨率自适应

`CarDimensions.scaleFor(窗口短边)` 在 **0.9x ~ 1.25x** 之间整体缩放。
基准是 1280x720；1024x600 走 0.9x，1920x1080 走 1.25x。

上限刻意压到 1.25：车机屏幕大但观看距离也远，需要的是"够大"
而不是"按比例同步放大"——放太大会让单屏信息量骤降、留白失控。

### 3. 触控尺寸按车机标准

`touchTargetMin = 56dp`（基准）而非 Material 的 48dp，
主操作按钮 68dp，列表行最小 60dp。
所有可点击行的**整行**都是热区，不是只有右侧控件可点。

### 4. 视觉层级：底色差异 → 1px 描边 → 浮层阴影，不叠第四种

- 卡片**默认不描边**，靠与页面底色的色差建立层级；
- 描边只出现在**选中态**与**输入框聚焦态**——它承担语义，不是装饰；
- **不使用阴影**：车机屏幕在强光/暗光下阴影几乎不可见，且离屏合成
  是车机 GPU 上不必要的开销。阴影只留给浮层（对话框）。
- **不使用真正的模糊（blur）**：Android 12 以下不支持，且是车机上
  明确的高耗能操作。

### 5. 图标自绘

全部是 24x24 描边图标，代码里的 SVG path，**不引入
`material-icons-extended`**：

- 引入它要改上游的 `gradle/libs.versions.toml`，多一个同步冲突点；
- Material 图标是"Android App 味"最重的视觉元素，
  直接会让界面露馅成"装在车机上的 APK"。

### 6. 浅色与深色同等支持

两套色板不是"主色 + 反色"：

| | 浅色（默认） | 深色 |
| --- | --- | --- |
| 页面底 | 冷调浅灰 `#F7F8FA` | `#17181C` |
| 卡片 | 纯白 | `#1D1F23` |
| 主色填充 | `#165DFF`（两套相同） | `#165DFF` |
| 主色文字 | `#165DFF` | `#6AA1FF`（深底上必须更亮） |
| 用途 | 白天强光下可读性最好 | 夜间 / 隧道 / 地库 |

主色**填充**两套相同，是因为白字压在 `#165DFF` 上的对比度（5.19:1）
与主题无关；真正需要随主题变的是"主色当文字用"时的取值。

默认跟随系统 `isSystemInDarkTheme()`，由宿主决定。
窗口首帧底色在 `car/app/src/main/res/values{,-night}/colors.xml`，
**必须与 `CarColors.background` 逐项对应**，否则冷启动会闪一次色。

## 连接状态主视觉

主页 = 连接状态页，结构只有两层：

```
[顶栏]                                          [⚙ 设置]
        ┌──────────┐
        │  ◯ 图标  │   ← 96dp 圆底 + 56dp 图标，底色随状态语义
        └──────────┘
           未启动                    ← displayLarge 30sp/500
     启动后自动连接 CarPlay            ← bodyLarge 15sp/400 textSecondary
        ────────────────            ← 4dp 不定量进度条（仅"进行中"显示）
     链路  无线   认证  本机软件认证     ← 关键参数表（label / value 两列）
```

### 为什么不再用插画

旧版是一幅 756 行的自绘插画（手机 → 连接线 → 应用坞 + 粒子 / 弹射 / 卡死
三种动效），另有一个 163 行的动画状态机。它的问题不是画得不好，而是
**信息效率为负**：

| 问题 | 说明 |
| --- | --- |
| 需要解码隐喻 | "手机""通道""坞"是比喻，用户得先翻译一遍才知道在等什么 |
| 状态靠"看动画"分辨 | 正常 / 卡死两种动效的差别要盯着看几秒；车机上没人会看 |
| 挤掉了真正有用的信息 | 整屏给了插画，"当前阶段""链路参数"反而没地方放 |

现在状态由**图标语义 + 文案 + 参数表**三样表达，全部是一瞥可读的静态信息。
动效只保留一条进度条，且只在"正在推进"时出现——**不做装饰性循环动画**。

### 图标与颜色成对推出

`CarStatusIndicator` 是唯一的状态语义，颜色映射只在
`StatusIndicators.kt` 里定义三处：

| 函数 | 返回 | 用途 |
| --- | --- | --- |
| `indicatorColor` | 强档色 | 图标、状态点、进度条 |
| `indicatorContainerColor` | 浅底档 | 图标圆底、状态胶囊底 |
| `indicatorOnContainerColor` | 浅底上的字色 | 状态胶囊文字 |

`HomeScreen` 的图标、`CarStatusView` 的圆底、`CarStatusPill` 的配色
**都由同一个 `indicator` 推出**，所以不会出现"绿色底配叉号"这种自相矛盾的组合，
也不会出现"连接失败在首页是红的、在设置页是橙的"。

### 状态文案的统一边界

未连接阶段的标题统一为 **"未启动"**、副标题统一为 **"启动后自动连接 CarPlay"**：
内部阶段（准备认证模块 / 等待认证模块 / 等待设备 / 连接中）对用户没有区分意义，
四种措辞只会让同一张页面看起来在跳字。

但 `ACTIVE` 和 `FAILED` **必须**保留各自文案：
投屏正在运行时显示"未启动"是**事实错误**，不是风格选择——
用户会以为没连上，然后去点"启动"。统一文案的边界到此为止。

同理，`WAITING_FOR_MFI` 的"请确认 MFi 认证模块已连接"虽然被统一掉了，
但它是唯一能看到"为什么连不上"的地方；产品上要恢复提示，
应该在 `NoticeCard` 里给，而不是把主标题拆回四种措辞。

### 连接页的版式取舍

**底部不放任何按钮，左上角不放标题。** 只保留右上角的设置入口。

- 连接页的主行动是"自动连接"，不是"按一下再连"。摆一个「启动 CarPlay」
  等于承认它不会自己启动——而副标题写的是"启动后自动连接 CarPlay"，两者互相打脸；
- 车机上的拇指可达区在屏幕下缘，但那正是空调/音量条常驻的位置，
  主按钮容易被车机自己的 UI 压住；
- 左上角的 "CarPlay / Android" 与页面中央的大字说的是同一件事，是纯噪音。

⚠️ **移除按钮时必须同时补上自动启动**，否则应用永远停在"未启动"。
`HomeScreen` 里的 `LaunchedEffect` 负责这一步，并且带 once 守卫——
失败后状态会回到"可启动"，没有守卫就会变成每次重组重试一次的死循环。

`NoticeCard`（权限被拒的提示）**保留**：它不是按钮，而是权限被拒后的
恢复入口。去掉它会把用户堵死在"无线 CarPlay 需要定位权限但没地方给"。
配色用 `warningContainer` 浅底块，不用描边也不用整块红底——
后者会读成"出大事了"，而缺权限只是"有一件事需要你处理"。

### ⚠️ 自动跳转画面页的判定必须在 `CarPlayApp`

会话激活后自动进入画面页，逻辑写在 **`CarPlayApp`** 而不是 `HomeScreen`。

原因是 `HomeScreen` 处在 `when (current)` 分支里，导航离开时会**退出组合**，
它内部的 `remember` 随之被丢弃。如果把守卫放在里面：

```
连上 → 自动进入画面页 → 用户按返回 → 回到主页
     → 守卫被重置 → 立刻又被弹回画面页 → 用户永远退不出去
```

另外两条约束：

- 会话结束时必须**解除**标记，否则断开再连不会自动进入；
- 只在**停留在主页**时才跳。用户正在设置页里操作时被强行拽走很讨厌，
  而那时他显然知道自己要干什么。

## 导航模型

```
主页  ──右上角齿轮──→  设置（二级）──→  设置分区（三级）
                              ├──→ 设备（三级）
                              └──→ 关于（三级）
```

无常驻导航栏、无快捷入口卡片：**这一屏的职责是"让用户一眼确认系统
在做什么"**，任何多余入口都会削弱这一点。设备/关于/设置全部从右上角进。
用页面栈（`List<CarDestination>`）实现，返回键逐级回退。

## 设置语义

修改只落在界面草稿，点「保存并重连」才提交。直接返回则丢弃。
（早期版本立即持久化，导致"随便点两下"就静默改掉配置，已纠正。）
